# 自然语言条件搜索与计划实际对照

入口为页面顶部“搜索或提问”。输入后打开查询窗口，可在“搜索结果”和“计划与实际”之间切换。本功能只读取当前账号的数据，不会修改计划、自动勾选完成或启动模型推理。

## 支持的提问

| 示例 | 识别的条件 |
| --- | --- |
| 找出上周没完成的英语任务 | 上周一至周日、未完成、关键词“英语” |
| 查看昨天的运动记录 | 昨天、运动类日常记录 |
| 最近七天学习计划与实际对照 | 含今天的最近 7 天、学习、对照模式 |
| 我这周原本打算学什么，实际完成了多少 | 本周一至周日、学习、对照模式 |
| 2026-11-01到2026-11-07学习对照 | 指定日期范围、学习、对照模式 |
| Python | 按字面关键词搜索 |

日期以浏览器当天为参照，支持今天、昨天、前天、本周/这周、上周、本月、上月、最近 N 天和 ISO 日期范围，最多 366 天。本周和本月包含尚未到期的安排，界面会提示。未指定日期的普通搜索覆盖所有日期；进入对照时默认本周。

这是有限语法的条件识别，不是任意语义问答。识别后的日期、类别、完成状态和关键词全部可见，可以修改后点击“按条件查询”。需要保留“学习”等词本身时，可把关键词放在引号中，例如 `学习“学习方法”的记录`。不调用 Ollama，因此无需排队，也不依赖 AI 服务在线。

搜索覆盖有效计划、学习目标、手动学习记录、菜品、未归档备忘和日常活动。日期或完成状态筛选时，目标与菜品这类无执行日期的数据不混入结果；完成状态只适用于计划。普通手动计划没有运动等活动分类，不自动推断分类归属。已删除的数据不返回，关联目标已删除的学习任务和学习时长也不计入。

## 对照口径

| 指标 | 数据来源与含义 |
| --- | --- |
| 计划事项、完成率 | 按计划日期归组，统计当前有效计划及当前完成状态；不表示“在该区间发生的完成动作次数” |
| 预计学习时长 | 区间内学习任务中明确填写的预计分钟；另列未填写的任务数，不平均分摊目标总时长 |
| 手动学习记录 | 按记录日期汇总实际分钟；没有记录显示“未记录”，显式记录 0 分钟则显示 0 |
| 已结束的专注计时 | 只计已结束计时与查询区间重叠的部分，按浏览器 UTC 偏移确定日期边界；进行中的计时不作为最终时长 |
| 日常活动 | 独立统计分类后的活动条数；不会从“学了两小时”等叙述中推算分钟或自动完成任务 |

手动记录与专注计时可能是同一次学习，分别展示，不相加为一个“实际总时长”。完成状态只影响搜索结果列表；对照仍使用相同时间、类别、关键词下的全部计划，避免“只看未完成”导致完成率分母改变。

统计基于完整匹配集合，结果和来源分别最多展示 100 条。超过上限时显示说明，缩小范围可查看其余条目。每条来源可返回对应计划日期、学习目标及记录页签，或日常记录日期，并高亮目标记录。

## 接口

`GET /api/v1/search/assist`

- `q`：问题或关键词，1—200 字符。
- `today`、`offset_minutes`：浏览器当前日期与 `getTimezoneOffset()`，用于相对日期及日界线。
- `start_date`、`end_date`：可选，一并传入以修改日期范围。
- `all_dates=true`：显式清除识别出的日期范围；无区间时对照面板提供本周入口。
- `category`、`status_filter`、`keyword`：可选，覆盖识别结果。
- `mode=compare`：进入对照；无日期时默认本周。

返回 `interpretation`（识别条件）、`results`、`total_count`、`comparison`（指标及来源）和 `warnings`。接口沿用现有认证及账号独立数据库，不接受跨账号数据路径参数。原 `/api/v1/search` 数组格式保留，并补入备忘与日常记录。

## 使用正式版本

本功能自 v0.1.1 起提供，最新 v0.1.2 完整本机版继续包含。下载新版 `PersonalHub.zip`，关闭旧程序、完整解压并启动新版 exe，即可在顶部“搜索或提问”使用。原有本机账号与记录继续保留，独立演示数据不会导入个人空间。

自行部署网站时，拉取最新 `main`、重新构建前端并重启后端；浏览器按 Ctrl+F5 刷新。GitHub 只保存代码，合并本身不会更新服务或旧 exe。具体步骤见[开发说明](DEVELOPMENT.md#更新到最新-main)。
