# 共享 AI 生成与等待

共享网页的学习计划和饮食计划支持后台生成。点击生成后，服务器先返回任务编号，页面用短请求查询状态，避免一直依赖同一条长连接。排队与正在生成分别显示，暂时的网络中断会查询同一个任务，不会重复提交一份计划。

- 最多三个账号同时生成，其他请求进入有长度限制的队列；同一账号不能同时提交不同生成任务。
- 排队时不扣每日次数；生成失败或取消后退回本次预留次数。
- 可以取消排队或生成。运行中的本地模型采用流式连接，收到取消信号后关闭连接，实际结束后才释放名额。
- 单次网络请求最多等待20秒，网络故障仅进行有限重试；整个排队和生成过程最多10分钟。超时会显示原因并停止等待，可以缩短计划天数后重新生成。
- 任务和结果只能由所属账号查看。服务重启后，内存中的生成状态会过期；已保存的草稿和正式计划仍保存在个人数据库中。

学习计划会检查每天是否落实用户填写的时间、步骤、成果和验收动作。只换日期、数字或知识点名称的重复步骤会被拦截并重写。轻量模型持续生成重复内容时，会先拆成不重复的每日子目标，再分别生成具体活动，最后按照原始目标检查整套计划，保留指定日期和每天的可用时间。仅写“确保理解”的验收会补充为与当天活动相符的可执行检查方法，用户仍可在草稿中修改。

本机模型的速度取决于电脑性能、计划天数和同时使用人数。建议试运行先生成2—7天，先查看并调整草稿，确认后再导入正式学习计划。该修复不会自动启用付费云端 AI。

自动测试使用模拟模型验证并发、取消、退回次数、账号隔离、网络重试及内容校验。可选的 `scripts/test-shared-model-live.py` 会调用本机已安装的真实模型，在新的 `.test-runtime` 目录创建独立测试账号；不修改实际用户的数据。`scripts/test-recycle-diet-browser.mjs` 则在隔离数据库中验证回收站、购物清单和热量预览。
