# PersonalHub 页面与交互规格

## 1. 全局框架

- 桌面优先，最小支持宽度 1180px。
- 固定左侧导航：总览、今日计划、学习计划、饮食计划、游戏娱乐、数据与设置。
- 顶栏：页面名称、全局搜索、快速新增、保存状态。
- 主区：列表、看板或周视图。
- 右侧详情抽屉：查看和编辑记录，关闭抽屉后保留列表上下文。
- 删除进入回收站；永久删除使用二次确认。
- 所有写操作显示保存中、已保存或保存失败。

## 2. 路由

| 页面 | 路由 |
|---|---|
| 首页总览 | `/` |
| 今日计划 | `/today` |
| 学习计划 | `/learning` |
| 饮食计划 | `/diet` |
| 游戏娱乐 | `/games` |
| 数据与设置 | `/settings` |

详情用路由查询参数表达，例如 `/learning?item=<id>`，从今日计划或搜索结果跳转后可以用浏览器返回。旧的 `/media`、`/development` 和 `/consulting` 地址统一返回首页。

## 4. 状态契约

- 计划事项：`pending`、`completed`、`cancelled`
- 计划分组：`must`、`scheduled`、`optional`
- 优先级：`low`、`normal`、`high`、`urgent`
- 游戏：`wishlist`、`playing`、`completed`、`paused`
- 保存状态：`idle`、`saving`、`saved`、`failed`

状态只能由后端接受的枚举值产生。界面显示中文，数据库和接口使用上述固定英文值。

## 5. 摘要规则

- 今日完成率：今日已完成且未取消数量 / 今日未取消总数量；总数为 0 时显示 0%。
- 逾期：计划日期早于今天且状态为 pending。
- 即将到期：今天之后三天内到期且状态为 pending。
- 学习：今日任务与本周完成任务数；若用户设置手动进度，优先显示手动进度。
- 饮食：按当前时间选择下一餐，显示今日饮水量。
- 游戏：正在玩的游戏和今日计划时长。

## 6. 删除、归档、取消和完成

- 完成：业务仍有效，但执行已结束。
- 取消：计划不再执行，保留历史原因。
- 归档：从日常活动视图隐藏，仍可查看和恢复。
- 删除：设置 `deleted_at` 并进入回收站。
- 永久删除：清除记录及其仅属于该记录的子数据，必须二次确认。

## 7. 交互状态

每个数据页面必须实现加载中、无数据、正常、保存失败和读取失败状态。失败时保留用户正在编辑的内容，允许重新保存。
